A quiet Friday window: three primary-source items landed across certificate automation, Kubernetes observability, and workflow orchestration. This is a short digest rather than a padded one.

## cert-manager 1.21.2 stops reflecting untrusted issuer responses into status

cert-manager published [v1.21.2](https://github.com/cert-manager/cert-manager/releases/tag/v1.21.2) on September 11, a patch release that closes several reliability and hardening gaps rather than adding features. The ACME issuer now excludes server response bodies from status conditions and Events, surfacing only structured ACME problem documents, and the Vault issuer no longer copies response bodies into `Ready` conditions. ACME server responses are also capped at 16 MiB to guard against an unbounded-body denial-of-service.

The release fixes a validating-webhook panic that fired when `AdmissionReview` requests omitted optional fields, a panic in the issuing controller when a `CertificateRequest` lacked a `Ready` condition, and a data race in the ACME HTTP-01 self-check against custom DNS servers. It also changes credential behaviour: the Vault issuer will no longer fall back to ambient AWS credentials for namespaced `Issuer` resources unless `--issuer-ambient-credentials` is set explicitly. Dependencies move to Go 1.26.8, `google.golang.org/grpc` v1.83.2, and `golang.org/x/crypto` v0.56.0. No CVEs are referenced.

**Source:** [cert-manager v1.21.2 release](https://github.com/cert-manager/cert-manager/releases/tag/v1.21.2) - September 11, 2026

## Kubernetes native histograms for component metrics graduate to beta

In a v1.37 spotlight [published September 11](https://kubernetes.io/blog/2026/09/11/kubernetes-v1-37-native-histograms-beta/), the Kubernetes project detailed native histogram support for its own component metrics, which reached beta and is now enabled by default. The change adopts [Prometheus native histograms](https://prometheus.io/docs/specs/native_histograms/) for latency and duration series such as API server request latencies and scheduling durations, replacing the classic fixed-bucket histograms.

Native histograms drop the need to predefine bucket boundaries, collapse the many per-bucket time series of a classic histogram into a single series, and remove the interpolation error that `histogram_quantile()` introduces on classic buckets. The practical consequence is lower cardinality and reduced scrape and storage overhead for cluster telemetry, but it requires a scrape and TSDB path that understands native histograms; teams pinned to classic-histogram tooling need to plan the migration before the format becomes the default they rely on.

**Source:** [Kubernetes blog](https://kubernetes.io/blog/2026/09/11/kubernetes-v1-37-native-histograms-beta/) - September 11, 2026

## Argo Workflows 4.1.3 fixes a progress-parsing panic and OpenTelemetry config

Argo Workflows cut [v4.1.3](https://github.com/argoproj/argo-workflows/releases/tag/v4.1.3) and the backported [v4.0.11](https://github.com/argoproj/argo-workflows/releases/tag/v4.0.11) on September 11, both maintenance patches for the CNCF-graduated workflow engine. The controller no longer panics while parsing progress, the OTLP exporter handles an empty endpoint without erroring, and the configured OpenTelemetry service name is now respected instead of being overwritten.

Other fixes cover daemon pod event handling after teardown, artifact plugin sidecar exit-code propagation, PostgreSQL token-auth DSN construction, database lock synchronisation reporting, and semaphore initialisation when the limit is zero. The release also bumps `golang.org/x/crypto` to v0.56.0 and `google.golang.org/grpc` to v1.83.2. There are no CVEs; this is an upgrade for operators tracking the 4.1 and 4.0 lines who hit the progress or telemetry bugs.

**Source:** [Argo Workflows v4.1.3 release](https://github.com/argoproj/argo-workflows/releases/tag/v4.1.3) - September 11, 2026
