Three primary-source releases landed in the last 24 hours across LLM inference serving, Kubernetes batch scheduling, and workflow security. Two carry breaking changes and one is a coordinated security fix, so this is a short digest built around what operators need to act on rather than a padded roundup.

## SGLang 0.5.20 retires CUDA 12 and makes ROCm 10 the default

SGLang published [v0.5.20](https://github.com/sgl-project/sglang/releases/tag/v0.5.20) on September 18, rolling up 713 PRs from 237 contributors. The change that matters most to operators is packaging: the release stops publishing CUDA 12 wheels and images (`-cu129` / `-cu12`), making v0.5.19 the final CUDA 12 build, and promotes ROCm 10 to the default AMD backend while retiring ROCm 7 CI and images.

Beyond packaging, the release removes prefill context parallelism v1 in favour of the strategy-based implementation and deletes several deprecated kernels, including `cutlass_mla`, non-Marlin GPTQ, AWQ AOT, and Dual Chunk Flash Attention. A reworked unified radix tree adds branching-point caching for sliding-window attention; the project reports the shared-prefix token hit rate rising from 43.8% to 60.8% on its benchmark. The Responses API also becomes opt-in, storing results only when `--enable-response-store` is set.

Teams that pin SGLang wheels or images need to plan the move off the CUDA 12 builds and audit for the removed kernels and CP flags before upgrading.

**Source:** [SGLang v0.5.20 release](https://github.com/sgl-project/sglang/releases/tag/v0.5.20) - September 18, 2026

## Kueue v0.20.0-rc.1 promotes v1beta2 and adds upgrade steps that can halt the controller

The Kubernetes batch scheduler Kueue tagged [v0.20.0-rc.1](https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.0-rc.1) on September 18. The release graduates v1beta2 to the primary served API and stops serving v1beta1, and the maintainers recommend running the migration script before upgrading.

Two changes can stop the controller or bypass quota if left unaddressed. Entries under the reserved resource name `pods` in DRA device-class mappings or resource transformations are now rejected, and the kueue-controller-manager will fail to start if any remain. The `LWSImmutableGroupSize` gate (beta, on by default) makes a LeaderWorkerSet's `leaderWorkerTemplate.size` immutable while Kueue manages it, closing a path where increasing that value let a workload run more pods than its reserved quota. Topology-aware scheduling also tightens validation: specifying `podSetSliceRequiredTopology` now requires a `podSetSliceSize` greater than zero.

This is a release candidate, so it is a preview rather than an upgrade target, but the v1beta2 cutover and the reserved-name and DRA-mapping rejections are worth testing now for anyone running Kueue for GPU or batch queueing.

**Source:** [Kueue v0.20.0-rc.1 release](https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.0-rc.1) - September 18, 2026

## Argo Workflows patches a path-traversal RCE and a cross-namespace archived-workflow leak

The Argo Workflows maintainers released [v4.1.4](https://github.com/argoproj/argo-workflows/releases/tag/v4.1.4) and [v4.0.12](https://github.com/argoproj/argo-workflows/releases/tag/v4.0.12) on September 18 to fix two high-severity vulnerabilities disclosed the same day.

[GHSA-vm9v-p987-xm32](https://github.com/argoproj/argo-workflows/security/advisories/GHSA-vm9v-p987-xm32) (CVSS 8.8) is a path-traversal flaw in directory-artifact materialization: the S3, GCS, and Azure Blob drivers join attacker-controlled object keys onto the download directory without containment checks, so a key containing `../` can write outside the workspace and overwrite files in the executor pod, up to remote code execution. It affects v4.1.0-v4.1.3, v4.0.0-v4.0.11, and all v3.x releases; v3.x gets no patch and must move to a fixed line.

[GHSA-q65w-j2vp-47c4](https://github.com/argoproj/argo-workflows/security/advisories/GHSA-q65w-j2vp-47c4) (CVSS 7.7) is a cross-namespace IDOR in `ListArchivedWorkflows`: a `metadata.namespace!=` field selector was authorized against the supplied namespace instead of cluster-wide, letting a namespace-scoped user read archived workflows, and their embedded parameters, from other tenants. It affects v4.0.0 through v4.1.3.

**Source:** [Argo Workflows v4.1.4](https://github.com/argoproj/argo-workflows/releases/tag/v4.1.4) and [v4.0.12](https://github.com/argoproj/argo-workflows/releases/tag/v4.0.12) releases - September 18, 2026
