Three primary-source releases landed in the last 24 hours across GPU inference serving, container runtimes, and messaging infrastructure.

## SGLang 0.5.18 overlaps checkpoint staging and reworks the TP LMHead path

The SGLang project published [v0.5.18](https://github.com/sgl-project/sglang/releases/tag/v0.5.18) late on August 24, rolling up 710 PRs from 212 contributors. The release concentrates on two costs that dominate large-model serving: cold-start time and per-token decode latency.

Overlapped checkpoint staging, enabled with `--startup-weight-load-mode overlap`, loads weights from storage while CUDA graphs are still being captured rather than serializing the two steps. SGLang reports Qwen3-32B on an H100 starting 8.6–11.7% faster than the serial-with-prefetch path and 2.38x faster than the default (35.6s versus 84.8s). A separate change collapses the tensor-parallel LMHead's allgather-plus-scatter into a single all-to-all for pure data-parallel attention; the project reports LMHead time on DeepSeek-V4-Pro B200 decode dropping from 320µs to 169µs.

The release moves the CUDA stack to PyTorch 2.13.0 with Triton 3.7.1 and FlashInfer 0.6.17. One breaking change to note on upgrade: compiled-kernel caches now consolidate under a single `SGLANG_CACHE_DIR`, which forces a one-time recompilation on first launch.

**Source:** [SGLang v0.5.18 release](https://github.com/sgl-project/sglang/releases/tag/v0.5.18) - August 24, 2026

## CRI-O 1.36.4 targets CPU and IRQ annotations per container

CRI-O shipped [v1.36.4](https://github.com/cri-o/cri-o/releases/tag/v1.36.4) on August 24, adding per-container targeting for its `cpu-load-balancing.crio.io`, `irq-load-balancing.crio.io`, and `cpu-quota.crio.io` annotations (PR #10152). Appending a container name to the annotation key scopes the setting to that container, and container-specific annotations take precedence over pod-level ones. Previously these applied to every container in a pod, so a pod that mixes a latency-sensitive workload with best-effort sidecars had to treat them identically. The release also fixes a nil-pointer crash in `ListPodSandboxStats` when a container's cgroup is torn down mid-teardown (PR #10216).

Alongside it, CRI-O cut [v1.35.7](https://github.com/cri-o/cri-o/releases/tag/v1.35.7) and v1.34.12 to backport the fix for CVE-2026-15809 (CVSS 7.8) to the older maintenance branches. The flaw is a bypass of the earlier CVE-2022-4318 fix: a newline byte in the `HOME` environment variable can inject lines into `/etc/passwd`, because the original check matched the literal string `\n` instead of an actual newline (PR #10201). The 1.36 line already carried the fix from v1.36.3 on August 4, so operators pinned to 1.34.x or 1.35.x are the ones this patch wave unblocks.

**Source:** [CRI-O v1.36.4 release](https://github.com/cri-o/cri-o/releases/tag/v1.36.4) - August 24, 2026

## NATS Server 2.15 previews a desired-state reconciliation engine for JetStream

The NATS project published [NATS Server v2.15.0-preview.1](https://github.com/nats-io/nats-server/releases/tag/v2.15.0-preview.1) on August 24, built on Go 1.27.0. The headline change is a desired-state reconciliation engine for JetStream streams and consumers, aimed at making placement updates and replication-factor changes safer while they are in flight rather than leaving assets in a partial state.

The engine ships with new operational primitives: `$JS.API.STREAM.CANCEL_MOVE` to abort an in-flight move or scale, server and peer evacuate endpoints (`$JS.API.SERVER.EVACUATE` and `$JS.API.STREAM.PEER.EVACUATE.*`) to drain a node for maintenance without removing the peer, and `$JS.API.META.RESCUE` for metalayer recovery. The release also adds a stream backup and restore v2 format that reads per message and correctly includes non-replicated consumers, plus source-stream recreation detection for faster lookups on restart.

This is a preview build for testing, not a production upgrade target, but the cancel-move and evacuate primitives address a long-standing gap in rebalancing JetStream clusters without risking data.

**Source:** [NATS Server v2.15.0-preview.1 release](https://github.com/nats-io/nats-server/releases/tag/v2.15.0-preview.1) - August 24, 2026
