# Durable review processing boundary

This implementation provides an executable Cloudflare Workflow boundary, a bounded Workers AI Whisper adapter, and a native Cloudflare Container/FFmpeg runner. The request Worker dispatches only the durable Workflow; a persistent non-production runtime owns the Workflow, Container, AI, and named Preview D1/R2 resources. The complete synthetic lifecycle has been exercised against the hosted Preview; arbitrary customer footage and production readiness remain separate gates.

## Admission, dispatch and attachment

A new additive migration creates internal `review_processing_jobs` records. The first processing request atomically captures the source key/ETag/SHA-256/size, server-selected output key, recipe SHA, model/chunk policy, expected current revision, start time and execution deadline, and moves the uploaded session to processing. No job is dispatched before this transaction succeeds. Upload acceptance/first admission still expires after one hour; a persisted job gets a fixed 24-hour execution deadline. Retrying after upload expiry resumes that job without extending its deadline. A completed result committed before the deadline remains available after expiry and after Workflow retention expires. Finalizing it through the intake API still requires an installed adapter with the original recipe, although it makes no new provider call.

`WorkflowMediaAdapter` creates the Workflow with the persisted session/job ID, recovers a lost acknowledgement by retrieving that exact ID, and returns processing promptly. It never awaits encoding from the HTTP request and never trusts `WorkflowInstance.status().output` as media evidence. Verified completion is retained in D1; terminal Workflow failure returns 409 and unfinished job expiry returns 410. An expired unfinished job requires a new intake. Cancellation remains available after either deadline; every provider step checks current job/session state, and completion/asset registration each use a D1 precondition to fence cancellation. No retry renews a deadline or picks a different job ID.

The expected current revision is nullable and immutable. On attachment, ReviewService checks it against the same state snapshot protected by the existing generation CAS. This guards replacement of the current revision ID; edits or approval on the same revision ID do not change that expectation. A late cut cannot silently supersede another cut, including when the captured expectation was no current revision. Stale completion retains its private verified assets and returns 409 on retries. There is no automatic expectation refresh. Existing ready sessions and revisions are retained; a pre-migration processing session without a durable admission record cannot invent a new deadline. Replaying a previously committed revision command still returns its original result.

## Workflow and providers

`ReviewMediaWorkflow` is separate from the existing fixture `MediaWorkflow`. Only job ID crosses the Workflow dispatch boundary; source keys, limits and policy come from D1. Encoding/probing and audio extraction/transcription run in parallel. Each successful stage is checkpointed by `step.do`; cancellation/deadline authorization is checked live inside callbacks and in the final transaction. Steps retry twice with exponential delay and a three-minute attempt limit. Container requests have a two-minute response limit.

The concrete `ContainerFFmpegClient` calls only a machine service binding at fixed encode/audio paths. Its protocol is `{protocol:1,job:<immutable manifest>}`. It accepts no customer URL, command line, output key override or browser callback. JSON responses are bounded to 256 KiB and remain untrusted until schema, job/source/recipe and R2-integrity validation. **An implementation owning a Cloudflare Container must still derive the reports from pinned executable FFmpeg/ffprobe code. This commit does not provide that implementation or make provider claims authoritative.**

The required runner must pin the source ETag and SHA while streaming, reject undecodable/oversize/overlong input, fully decode and inspect output, encode H.264/AAC fast-start MP4 with bounded output, and stream immutable R2 writes with native SHA-256 validation. Encode and audio operations must be independently idempotent for the same job/recipe, survive Workflow retries and stop at the persisted deadline. Audio keys are selected as `review-intake/<job>/audio/<index>.wav`; the source/deliverable keys remain the intake-selected keys. A future deployed image digest and fixed argument/resource/network policy must determine the recipe SHA; an arbitrary service that echoes JSON must never be installed in its place.

The implemented Whisper adapter calls the Workers AI binding with `@cf/openai/whisper-large-v3-turbo`, a bounded base64 audio chunk, `task:transcribe` and VAD enabled. It checks each chunk's stored SHA/ETag/size, conditionally reads it, enforces length and rehashes the actual bytes before sending them to AI. Provider text is schema/length checked. Transcripts are editorial data: generated text fills an empty transcript on the new revision, while existing staff-authored text is preserved. It does not approve or publish content.

Pinned expansion limits are deliberately narrower than the older probe schema: two hours of media, at most 120 contiguous one-minute chunks, two MiB per chunk, mono 16 kHz PCM WAV, one Whisper call in flight, 10,000 characters per chunk and 100,000 total transcript characters. Chunk keys, indices, coverage, source and recipe must match. Extracted duration/audio presence must agree with encoded evidence. The existing 64 MiB source/deliverable cap remains. The named Workers AI model is a managed alias; this does not assert immutable upstream model weights. A timed-out AI request can have executed before a retry, so paid calls are not exactly-once.

## Configuration and remaining activation gates

Production, ephemeral Preview, and the persistent Preview runtime declare separate `REVIEW_MEDIA_WORKFLOW` and AI bindings. The request Preview explicitly names the existing Workflow host with `script_name`; it does not pretend that a Preview-specific Workflow was provisioned. AI is explicitly `remote:false` for local development. The Container image and recipe are pinned, and the runtime is deployed without a public route.

The hosted synthetic path verified the native Container bridge, R2 artifact writes, Workers AI transcription, Workflow retries/checkpoints, and review attachment. Remaining gates are real customer-footage acceptance, capacity/quotas/cost controls, production Container permission, production deployment, and public watch-page integration. Container deployment follows Cloudflare's supported Container/Durable Object API and configuration. Media Transformations was not adopted or represented as supplying FFmpeg evidence.

Abandoned source/audio/output cleanup and storage quotas remain gates. Cancelled work may already have an in-flight provider call; D1 rejects its completion, but this slice does not terminate a remote Container or delete objects. A reaper must confirm job termination, apply a grace period and recheck immutable asset/publication references. It must never delete successful deliverables retained at intake keys. A blanket lifecycle rule on that prefix is unsafe.

## Verification

- Payload TypeScript check and all **108** package regression tests passed; 22 focused intake/processing tests passed, including lost dispatch acknowledgement, concurrent admission, fixed deadline, post-expiry cancellation, retained completion, nullable/current revision protection, migration compatibility, parallel provider flow, Whisper byte validation and bounded Container JSON.
- Wrangler `types --include-runtime=false` succeeded independently for production and review-preview configuration, including the new Workflow export and AI binding. The full preview `deploy --dry-run` stopped before bundling because `.open-next/assets` is absent in this isolated checkout; this does not establish a packaged/deployable OpenNext backend.
- Existing local Miniflare 5/workerd intake smoke passed again: actual bridge/service-binding upload, native FixedLengthStream/R2 checksum validation, retries and provider-absence 503. The new processing tests use a simulated Workflow binding/step runner, local SQLite and fake Container/AI providers; no real Workflow execution, Container, FFmpeg encode, Whisper inference or deployed OIDC flow was verified.
- Independent read-only review found no blocking issue with provider activation disabled; same-revision edits/approval and original-recipe availability are the non-blocking limitations described above.
- `cuenv sync -A` was attempted first and failed on the existing CLI/schema/pruned-checkout/CUE-registry environment issues. Already-installed dependencies were used. The persistent Preview runtime and named Preview were deployed with the host's authenticated Wrangler session; production was not deployed, no production migration/import was run, and no custom DNS was changed.
